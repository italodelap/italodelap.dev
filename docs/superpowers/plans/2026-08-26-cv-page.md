# CV Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve a condensed, recruiter-friendly CV at `/resume` (reusing existing site data), and move the current narrative resume page to the unlinked `/profile` route.

**Architecture:** A new `CvLayout` + five focused `src/sections/cv/*` components compose the CV page, driven entirely by existing `site.json` config and the `work-experience` content collection plus one new optional `highlights` field that opts a position into the CV. The current `src/pages/resume.astro` is renamed to `src/pages/profile.astro` with zero internal changes, and a brand-new `src/pages/resume.astro` takes over the route.

**Tech Stack:** Astro 7 (SSG) + TypeScript + Tailwind CSS v4, Zod schema validation via Astro Content Collections, pnpm.

**Spec:** `docs/superpowers/specs/2026-08-26-cv-page-design.md`

## Global Constraints

- No generated static PDF artifact — "PDF" means the browser's native print dialog, triggered by a visible print button and/or Ctrl/Cmd+P.
- No Skills/tech-stack section on the CV (explicitly out of scope).
- `src/pages/profile.astro` (renamed from the current `resume.astro`) keeps its content, layout, and copy byte-for-byte unchanged — only the file path changes.
- The CV page renders fixed-light only: no `dark:` utility classes anywhere in its markup, and it does not mount `ThemeToggler`.
- No sitemap/robots changes for `/profile` — it stays technically indexable, it just loses its only internal link.
- Visual direction is mockup Option C (already approved): neutral sans-serif base, a single accent color (`indigo-700`, i.e. `#4338ca` — matches the approved mockup swatch) used only for the name and section headings, monospace (`font-space-mono`) reserved for dates and location, no per-company color-coding, no background gradient, denser spacing than `/profile`.
- This repo has no test runner configured (confirmed via `package.json` and AGENTS.md — only `astro check` via `pnpm build`). Every task's verification step is `pnpm build` plus, for UI-facing tasks, a manual check via the Astro dev server (`pnpm dev`, or `astro dev status`/`astro dev logs` since Astro 7 backgrounds it for agents per AGENTS.md).
- Package manager is pnpm (`pnpm-lock.yaml`) — use `pnpm`, not `npm`/`yarn`.
- Path alias `@/*` → `src/*` is already configured; use it in all new imports, matching existing files.

### Task 1: Add `highlights` field to the work-experience schema

**Files:**
- Modify: `src/content.config.ts`

**Interfaces:**
- Produces: an optional `highlights: string[] | undefined` field on both the top-level `work-experience` entry schema and each item inside its `subitems` array. Task 2 (content curation) and Task 10 (`Experience.astro`) depend on this exact field name and type.

- [ ] **Step 1: Add the field to both places in the schema**

In `src/content.config.ts`, add `highlights: z.array(z.string()).optional(),` to the top-level object and to the `subitems` item object:

```ts
import { defineCollection } from "astro:content";
import { glob } from "astro/loaders";
import { z } from "astro/zod";

const workExperience = defineCollection({
  loader: glob({ pattern: "**/*.(md|mdx)", base: "./src/content/work-experience" }),
  schema: z.object({
    company: z.string(),
    cover: z.object({
      src: z.string(),
      alt: z.string(),
    }),
    from: z.coerce.date(),
    highlights: z.array(z.string()).optional(),
    position: z.string(),
    shadow: z.string(),
    summary: z.string(),
    title: z.string(),
    to: z.coerce.date().optional(),
    subitems: z.array(z.object({
      from: z.coerce.date(),
      highlights: z.array(z.string()).optional(),
      position: z.string(),
      summary: z.string(),
      to: z.coerce.date().optional(),
    })).optional(),
  }),
});

export const collections = { "work-experience": workExperience };
```

Run: `pnpm build`
Expected: PASS — the field is optional, so the 5 existing content files (none of which have `highlights` yet) still validate against the schema.

### Task 10: Create `src/sections/cv/Experience.astro`

**Files:**
- Create: `src/sections/cv/Experience.astro`

**Interfaces:**
- Consumes: the `work-experience` collection, `getSortedExperience()` (`src/lib/sorting.ts`, unmodified), `ExperienceDuration` (`src/components/ExperienceDuration.astro`, unmodified), the `highlights` field from Tasks 1–2, and `titleClass` from Task 7.
- Produces: a `.cv-entry` class on each rendered `<li>` (top-level job with no curated subitems, or each curated subitem), matching the print contract `CvLayout` (Task 6) defines.
- Filtering rule: a top-level job renders only if it has its own `highlights` OR at least one subitem with `highlights`. A job with curated subitems renders its subitems' highlights nested under the company name (no top-level bullet list in that case); a job without subitems renders its own `highlights` directly. Jobs with neither (e.g. Tupaca) are omitted entirely.
- Company names and dates use no accent color (per "no per-company color-coding" and "accent reserved for name + section headings") — dates stay monospace and muted (`text-neutral-500`), matching Task 8's date styling.

- [ ] **Step 1: Create the component**

```astro
---
import { getCollection } from "astro:content";
import type { CollectionEntry } from "astro:content";

import ExperienceDuration from "@/components/ExperienceDuration.astro";
import ResumeSection from "@/components/ResumeSection.astro";

import { getSortedExperience } from "@/lib/sorting";

type Subitem = NonNullable<CollectionEntry<"work-experience">["data"]["subitems"]>[number];

function hasHighlights(entry: { highlights?: string[] }): boolean {
  return Boolean(entry.highlights && entry.highlights.length > 0);
}

const workExperience = await getCollection("work-experience");
const sortedWorkExperience = getSortedExperience(workExperience);

const curatedExperience = sortedWorkExperience
  .map((job) => {
```
